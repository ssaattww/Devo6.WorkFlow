# Issue #18: engine 設定 YAML 初期生成

状態: 提案中

## 目的

NuGet tool として導入した利用者が、CLI に同梱された engine 設定を作業ディレクトリへ安全にコピーできるようにする。

## 実装方針

初版では `engine init [--directory DIR]` を追加し、配布物の `config/engine.defaults.yaml` から `engine.yaml` を生成する。生成した設定は、既存 CLI の規則に従って `engine run ENTRY --engine-config PATH` と明示して使う。初期化時に Entry は読み込まず、workflow の `run` も行わない。

設定対象が未指定のため、engine 設定のみを生成する案を推奨する。engine 設定は CLI に共通の既定値が同梱されており、配布物から生成できる。workflow 設定は Entry ごとに必要な値が異なる。空の YAML は既存ローダーで使える場合もあるが、必要値を満たす保証はないため、初版の出力には含めない。

## 実装詳細

### 入力とパス

`--directory DIR` は任意とし、省略時の出力先はカレントディレクトリとする。相対ディレクトリはプロセスのカレントディレクトリ基準で解決する。指定ディレクトリが存在しない場合は自動作成せず、I/O エラーとして終了する。

### 生成と競合

出力名は `engine.yaml`。配布物内のテンプレートを、出力先と同じディレクトリに一時ファイルとして作成し、全内容を書き終えて閉じてから `engine.yaml` へ上書きなしで確定する。確定時の既存ファイル競合は I/O エラーと区別して報告する。処理が制御を保てる場合は、この実行が作成した一時ファイルを競合時と失敗時に回収する。強制終了では一時ファイルが残り得るが、確定名に不完全な内容は残さない。再実行時は他の処理が使用している可能性がある一時ファイルに触れない。既存の `engine.yaml` は読み書きせず、リンクや同名のディレクトリも置換しない。

| 終了コード | 条件 |
| --- | --- |
| 0 | `engine.yaml` を生成した |
| 1 | 出力先が既存ファイルと競合した、またはディレクトリ・読込み・書込み・確定などの I/O に失敗した |
| 2 | コマンド名または引数が不正 |

競合と I/O エラーは終了コード 1 を共有し、診断メッセージで区別する。失敗後に不完全な `engine.yaml` を残さない。一時ファイルの回収にも失敗した場合は、そのパスを診断する。

### 実行時の利用

`engine init` はファイル生成だけを行う。Entry の探索、ファイルの読込み・評価、Provider・Step の生成、NuGet 復元、ビルドは開始しない。生成したファイルは、たとえば `engine run ./main.csx --engine-config ./engine.yaml` と指定して使う。既存 CLI は相対 `--engine-config` を Entry ファイルのディレクトリ基準で解決するため、Entry と設定ファイルの場所が異なる場合はその基準に合うパスを指定する。

## 受け入れ条件

- [ ] `engine init` は既定でカレントディレクトリに `engine.yaml` を生成する。
- [ ] `--directory DIR` の相対・絶対パスを解決し、存在しないディレクトリは作成せずエラーにする。
- [ ] テンプレートは配布物から読み、リポジトリのソースツリーに依存しない。
- [ ] 一時ファイルへの全書込み後に非上書きで確定し、競合・I/O エラーを別の診断として示す。
- [ ] 失敗後に不完全な `engine.yaml` が残らない。回収できる失敗では、この実行が作成した一時ファイルを回収する。
- [ ] 終了コード 0／1／2 と利用例を README に記載する。
- [ ] 生成した設定を `--engine-config` で指定した `run` と既存の `run`／`validate` の契約を保つ。
- [ ] 初期化は Entry、Step、file-based workflow Provider を実行しない。
